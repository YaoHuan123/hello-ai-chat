## 产品定位与发布平台

- **产品形态**：面向 **30 岁以下** 用户的 AI 社交娱乐应用（原生壳 + Web 技术栈），偏 **社交前置、非正式**，不是微信式严肃通讯录。
- **三大功能**：① 辅助聊天（Mol，向内练表达）② 单向探索式朋友圈（向外挂资料供熟人探索）③ AI 群聊（2 真人 + N 护场角色，在场娱乐与护场）。护场角色与 Mol 世界**分体系**，勿混称。
- **聊天存储**：[聊天本地存储原则](./聊天本地存储原则.md)——**所有聊天内容仅存本机，服务端不存、换设备丢失**。
- **发布节奏（V1）**：**仅支持 Android**；iOS 与独立 Web 端暂缓，后续按产品节奏扩展。
- **工程实现**：复用 **`frontend/`** 的 Vite + React，通过 **Capacitor** 生成 Android 工程（`frontend/android/`），与参考仓库 `E:\happy story\frontend` 一致。
- **账号与接口**：V1 账号能力（短信注册/登录、注销）由本仓库 **`backend/`** 提供 HTTP API；联调时 Android 模拟器使用 `http://10.0.2.2:<PORT>` 访问宿主机后端。

### 被动展示（熟人探索区）

- **定位**：更接近**被动挂起的个人空间**（类朋友圈的展示逻辑，但不依赖刷屏发动态）：内容由本人填写或确认，**熟人带着问题来探索**；缓解「不爱发朋友圈、又希望被了解」的矛盾。
- **与辅助聊天的分工**：辅助聊天侧重话术与表达；被动展示侧重**观点、偏好、事实类信息**（例如理想型、兴趣边界），适合不便发在公域朋友圈、又愿写入可控区域的内容。
- **信任与合规边界**：探索方可见范围应限于**本人已填写或已授权展示**的内容；产品表述与行为须一致，**不得暗示** AI 能代表本人给出未填写、未授权的态度或现场答复。若保留「他人提问」入口，聚合结果仅作**待本人补全**的引导，避免沦为「套取心意」的虚假代言。

## 一、产品功能表

### 1.1 按模块

| 模块 | 功能点 | 说明与边界 |
|------|--------|------------|
| A 账号 | 登录/登出/会话保持 | JWT + `Authorization`；前期可 mock。 |
| B 辅助聊天 | 与**真人**对话，Mol 在侧 | Mol 提供推荐/修饰，默认**写入输入框**再发。 |
| C 熟人探索（访客） | 他人在授权范围内查看/探索**我的被动展示** | 仅展示已授权资料；可选轻量提问形态，答复须遵守上文「信任与合规边界」。 |
| D 补全（主人） | 根据他人探索产生的**待填问题**或系统热门题 | 本人答题/补全，写入被动展示数据。 |
| E 被动展示数据 | 「使用中」等已写入数据 | 查看、删除与有限编辑；与 D 分工：D 偏采题与引导，E 偏存量管理。 |
| F Mol 本体 | 形象+提示+数据 | 选 Mol、切 Mol。 |
| G Mol 世界 | 商城、购买/解锁、能力展示 | 可展示**示例对话**（脱敏策略待定）。 |
| H Mol 训练 | 调参/定制 | 与 E 有分工：训练偏显式；补全（模块 D）偏题目引导。 |
| I Mol 输出 | 自动/润色、**多步分支** | 如先选接受/再选话术。 |
