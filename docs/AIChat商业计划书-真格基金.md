## 一页摘要（Executive Summary）

**一句话**：AIChat 是面向 30 岁以下用户的 **AI 关系操作系统**，产品按 **三大维度** 展开——**关系社交**（素颜 / 搭子 / 探索式朋友圈）、**日常**（个人生命轨迹的私人记录空间）、**YiYi**（中间人匹配）——在真人社交之上，帮助用户更从容地表达、被了解、护住边界，并认识合适的人。

**我们在解决什么**：年轻人不是不想社交，而是 **不会说、不敢发、聊崩了没人帮**；现有社交产品几乎都在 **费力表演给别人看**，却普遍缺少 **关注自己、记录自己、取悦自己** 的空间；同时需要 **低压力认识新人** 的路径。微信解决「连得上」，Soul/探探解决「找得到」，但 **关系增强、私人生命档案、规则化 pre-matching** 仍是空白。

**产品形态**：原生 App（Android V1 已开发，iOS 在途），**三大维度并列、边界清晰**；关系社交维度的聊天内容默认仅存本机，AI 全部经服务端调用、不静默降级。

**为什么是现在**：大模型使「场景化 AI 角色接话」成本降至消费级；Z 世代对 AI 辅助表达接受度显著高于上一代；短视频可低成本验证「关系小剧场」需求，无需双边社交冷启动。

**融资诉求**：寻求 **人民币 300–500 万元** 天使投资，用于 12–18 个月产品完善、冷启动验证与合规上架，目标达成 **1 万 MAU、护场群创建率与 YiYi 有效匹配的可量化验证**。

**商业化方向（12 个月以后）**：变现主战场仍在 **维度一 · 关系社交**（搭子单品 + 素颜订阅）；**维度二 · 日常** V1 免费，V2 起可通过 **AI 生命叙事**（一键成文/成片）与备份扩容 monetize；**维度三 · YiYi** 待匹配验证后再评估。

**我们请求真格关注的，不是「又一个 AI 聊天工具」，而是「AI 如何嵌入真实关系链、且用户仍掌握最终话语权」这一产品范式。**

## 一、问题与洞察

### 1.1 用户真实痛点（按产品维度）

| 产品维度 | 场景 | 用户心声 | 现有产品为何不够 |
|----------|------|----------|------------------|
| **维度一 · 关系社交** | 私聊 | 「看到了消息，但不知道怎么回才不尴尬」 | 输入法、Copilot 不懂关系语境与语气边界 |
| **维度一 · 关系社交** | 群聊 | 「俩人聊僵了，需要第三方给台阶」 | 微信拉闺蜜进群太重；AI 单聊无法模拟「在场」 |
| **维度一 · 关系社交** | 朋友圈 | 「不想刷屏，又希望熟人能了解我的观点」 | 微信朋友圈是表演场；问卷/资料卡太冷 |
| **维度二 · 日常** | 自我记录 | 「社交里都在表演，我想有一块只属于自己的地方」 | 朋友圈/动态是发给别人看的；日记 App 与社交割裂；缺 **个人生命轨迹** 的连续归档 |
| **维度二 · 日常** | 育儿记录 | 「几乎每天都给娃拍照，但和手机里其它照片混成一团，根本找不回来」 | 系统相册按时间平铺，与工作照、截图、外卖图混在一起；专门做宝宝相册的 App 又与社交/生活割裂 |
| **维度三 · YiYi** | 认识新人 | 「想认识同类人，但不想被尬聊和越界骚扰」 | Dating App 直连真人，缺少缓冲层与规则 |

### 1.2 核心洞察

1. **AI 社交的正确位置是「增强真人关系」，而非替代真人。** 用户要的是「我想好了再发」，不是「AI 替我聊完」。（维度一）
2. **表达、护场与被了解，同属「关系社交」，但机制不同。** 素颜解决「怎么说」；搭子解决「在场护边界」；探索式朋友圈解决「怎么被熟人了解」——三者共享真人关系网络，构成同一产品维度。（维度一）
3. **私人记录与对外社交必须分维。** 「日常」是 **个人生命轨迹的私人档案**，只服务本人，不进入任何探索、匹配或好友可见链路。（维度二）
4. **现有社交产品的结构性缺失：只有「演给别人看」，缺少「关注自己」。** 行业默认逻辑是发动态、争曝光、换认可；AIChat 在维度二中补上一块 **类似私人网盘的生命记录空间**——记录自己、回看自己、取悦自己，与维度一的「表演式社交」形成对照。（维度二）
5. **手机相册不是生命轨迹档案。** 宝妈等高频记录者每天拍照，素材却与截图、工作照、杂图混存， **按「人生阶段/主题」连续回看** 极难；朋友圈晒娃则是表演给亲戚看，不等于为自己留存。（维度二）
6. **认识新人需要中间层，而非 Direct DM。** YiYi 在双方主人见面前完成试探与规则过滤。（维度三）
7. **隐私是信任前提。** 关系社交维度的聊天本地存储；探索仅基于已授权资料；YiYi 设「垃圾桶」与可见范围——各维度合规边界独立、表述一致。

### 1.3 为什么是现在

- **模型成本**：单次护场接话 / 回复建议 API 成本已降至可规模化运营区间。
- **用户心智**：2024–2026 年，18–28 岁用户对「AI 帮我组织语言」的羞耻感快速下降。
- **分发窗口**：抖音等平台允许以「关系冲突小剧场」录播获客，避开传统社交 **双边冷启动** 陷阱。
- **监管边界清晰**：不做虚拟伴侣替代真人、不自动代发、不越权代表用户——合规路径可 walk through。

## 二、产品方案

### 2.1 产品定位

**AIChat = 三大维度并列的 AI 关系操作系统**

- **不是** 微信替代品、不是纯 AI 陪聊、不是 Dating App、不是纯日记 App。
- **是** 在清晰分维的前提下，分别服务：**已有真人关系的 AI 增强**、**仅对自己的生活记录**、**规则化的认识新人**。

**Slogan（按维度）**：

| 维度 | 一句话 |
|------|--------|
| 关系社交 | 和真人聊，不被话术卡住；不发朋友圈，也能被熟人了解；关键对话有人帮盯场 |
| 日常 | 关注自己，记录生命轨迹，只为自己留存 |
| YiYi | 先让中间人聊清楚，再决定要不要认识 |

### 2.2 三大产品维度（总览）

这是 AIChat 的 **顶层产品架构**。所有功能归属以下三维度之一，**不跨维混用数据与心智**。

| 维度 | 名称 | 包含能力 | 核心对象 | 是否对外可见 | 商业化（12 月后） |
|------|------|----------|----------|--------------|-------------------|
| **维度一** | **关系社交** | 素颜 · 搭子 · 探索式朋友圈 | 已有/将有的 **真人** 关系 | 是（在授权范围内） | **主战场**：搭子单品 + 素颜订阅 |
| **维度二** | **日常** | 个人生命轨迹 · 私人网盘式记录（照片/视频/文字/语音） | **仅用户本人** | **否** | V1 免费；V2+ AI 叙事 |
| **维度三** | **YiYi** | 画像 · 对话 · 中间人匹配 · 权限 | **陌生人 / 潜在新关系** | 按权限可控 | 验证后再评估 |

**维度边界（必须遵守）**：

- **关系社交 vs 日常**：维度一是 **演给别人看**（动态、探索、护场）；维度二是 **记给自己看**（生命轨迹归档）。「我的动态」供熟人探索；「日常」**不对任何人展示**，二者不得混用数据与心智。
- **关系社交 vs YiYi**：素颜/搭子服务已建立的联系人；YiYi 服务 **尚未建立** 的关系，双方 YiYi 试探后才推送摘要。
- **搭子 vs 素颜**（同属维度一）：catalog 独立——搭子服务 **群聊护场**，素颜服务 **私聊表达**；商城与付费分开设计。

### 2.3 维度一 · 关系社交

**定位**：在 **真人关系链** 上叠加 AI 能力，分三条能力线，共享联系人网络与信任前提。

| 能力线 | 方向 | 机制 | Tab / 入口 |
|--------|------|------|------------|
| **素颜** | 向内 · 练表达 | 与真人私聊时切换表达人格，生成 2–3 条回复建议，**用户确认后发送** | 消息 |
| **搭子** | 在场 · 护边界 | 2+ 真人 + 最多 3 个场景化 AI 搭子；按人设接话、调解、风险提示 | 群聊 |
| **探索式朋友圈** | 向外 · 挂资料 | 维护「我的动态」；熟人带问题探索，AI **仅基于已填资料** 作答；含热点选题、探索记录 | 朋友圈 |

**维度一 · 差异化小结**：
- 素颜：人格可自建、可从「素颜世界」加入；按会话记忆切换。
- 搭子：护场角色 catalog 独立；群主可见 owner hints；抖音传播主场景。
- 探索式朋友圈：不刷屏、不表演；问答式了解；**不得** 代表用户给出未授权态度。

**维度一 · 隐私**：私聊 / 群聊 / 探索对话 **仅存本机**；服务端转发不持久化气泡；探索资料为用户主动填写项。

### 2.4 维度二 · 日常

**定位**：补全当前社交产品的 **结构性缺失**——行业长期只有「发给别人看」的发声渠道，缺少 **关注自己、记录自己、取悦自己** 的专属空间。AIChat 将「日常」定义为 **个人生命轨迹的私人档案库**，形态上接近 **仅对自己开放的网盘**：持续归档照片、视频、文字与语音，按时间线回看，构成只属于用户自己的生命记录。

**与行业现状的对照**：

| | 典型社交产品 | AIChat · 日常 |
|--|--------------|---------------|
| 核心动作 | 发布、曝光、求互动 | 记录、归档、回看 |
| 默认观众 | 好友 / 公众 | **仅本人** |
| 内容性质 | 表演、筛选、人设维护 | 真实、随意、无需取悦他人 |
| 时间价值 | 即时动态，易被信息流淹没 | **生命轨迹**，按日留存、可持续纵向回看 |

**能力构成**：

| 项目 | 说明 |
|------|------|
| 记录方式 | 拍照、拍视频、写文字、语音；底部 Dock 快速入口 |
| 浏览方式 | 按日分组的时间线，回看个人生命轨迹 |
| 可见性 | **仅用户本人**；不对好友、探索、YiYi 或任何 AI 分身展示 |
| 存储 | 本机（V1）；不上传、不同步、不参与推荐与社交分发 |
| 与「我的动态」区别 | 「我的动态」是维度一中 **对外探索资料**；「日常」是 **纯私人生命档案** |
| 与手机相册区别 | 系统相册是 **所有照片的杂糅堆**；日常是 **有意图的生命轨迹归档**——拍娃、拍生活，进入即分类留存，不与截图/工作照混在一起 |

**典型场景 · 宝妈育儿记录**

一位宝妈 **几乎每天都会给娃拍照**，动机不是发朋友圈表演，而是 **怕错过成长、想留给未来的自己看**。现实中她面临两个坏选项：

| 方式 | 问题 |
|------|------|
| **直接存手机相册** | 与外卖截图、工作文档、杂图混在一起；日子一久想回看「宝宝第一次走路」，要在上万张图里翻 |
| **发朋友圈晒娃** | 默认观众是亲戚同事；要配文案、控频率、担心打扰别人—— **记录变成了表演** |

**日常 Tab 提供的第三种方式**：

- 打开 App → 日常 → 拍照：这条记录 **直接进入生命轨迹时间线**，与手机系统相册 **物理分离**。
- 按日浏览：「3 月 15 日」下就是那天关于娃的照片、短视频、一句随手语音—— **主题与时间绑定**，不是相册里的一个像素点。
- 不对任何人可见：不必纠结「发不发朋友圈」； **先为自己记，是否对外分享由用户另行决定**。
- V2+ **AI 生命叙事**：一键生成「宝宝本月成长记」短文或纪念短片—— **取悦自己**，给宝妈在深夜哄睡娃后的一次「回看仪式」。

此场景说明：维度二不仅是抽象「日记」，更是 **家庭阶段、育儿周期等人生切片** 的 **专用归档通道**；与维度一「我的动态」（可被熟人探索的观点/偏好）完全不同。

**维度二 · 产品价值**：

1. **补行业空白**：在「社交 App」内首次明确划出 **非表演区**，与维度一形成「对外关系 / 对内自我」的双轨结构。
2. **提升长期粘性**：生命轨迹随时间累积，切换成本与情感依附随记录增加而上升。
3. **品牌差异化**：向用户与市场传递——AIChat 不只有「帮你在关系里做得更好」，也有 **「帮你把日子留给自己」**。
4. **承接高频记录人群**：宝妈、备考者、健身记录者等 **主题化日常拍摄** 用户，系统相册给不了「按人生故事归档」的体验。

**维度二 · 商业化（分阶段）**：

| 阶段 | 方向 |
|------|------|
| V1 | 完全免费；记录与按日回看 |
| V1.5 | 扩容、加密备份、导出（网盘式增值） |
| **V2+** | **AI 生命叙事**（见下）；按生成次数或订阅覆盖 API 成本 |

**维度二 · 演进路线：AI 生命叙事（V2+）**

依托文生图、图生视频、多模态理解等成熟能力，在 **用户授权的本机/私有归档** 之上，提供 **一键把日常记录融合为文本或视频** 的功能——服务对象仍是 **用户本人**，默认 **不进入任何社交分发链路**。

| 能力 | 输入 | 输出 | 用户价值 |
|------|------|------|----------|
| **一键成文** | 某日 / 某月 / 某主题的图文与语音 | 日记式散文、周报、月度小结 | 把碎片记录变成 **可回读的生命叙事** |
| **一键成片** | 同时间范围内的照片与短视频 | 带配乐与字幕的个人纪念视频 | **取悦自己** 的仪式感，而非发朋友圈 |
| **轨迹回顾** | 年度或自定义区间全量记录 | 「这一年」长文 / 年度影片 | 强化「个人生命轨迹」的长期价值 |
| **主题叙事（例）** | 宝妈在某月内关于宝宝的全部日常记录 | 「宝宝 × 月成长记」/ 成长短片 | 碎片不再淹没在手机相册里， **一键还给自己一段完整故事** |

**与维度一的边界**：

- 维度一 · 探索式朋友圈：资料供 **他人** 了解你。
- 维度二 · AI 叙事：把记录 **还给你自己**——帮你看见自己过过的日子。
- 用户 **主动导出** 至相册或分享至外部平台时，行为发生在 App 外，产品不默认替用户「表演」。

**实现原则**：

1. **先文本、后视频**：文本摘要 API 成本低、迭代快；成片依赖图生视频，按区间/次数计费更可控。
2. **本地优先**：生成任务可基于本机已归档素材；上传云端须 **显式授权**，与「日常不对任何人展示」一致。
3. **不静默生成**：用户点击「生成」才调用 AI，失败明确报错，不做偷偷加工。
4. **变现路径自然**：高成本的多模态生成（尤其视频）可作为维度二 **首个付费点**，与维度一搭子/素颜形成互补收入线。

**维度二 · 传播原则**：不参与抖音获客主叙事（维度一 · 搭子承担）；AI 叙事能力可通过 **用户自发导出年度片** 形成弱传播，但不作为默认产品路径。

### 2.5 维度三 · YiYi

**定位**：**中间人层**，在双方主人正式认识前，由 YiYi 完成画像沉淀、匹配与试探沟通。

| 模块 | 机制 |
|------|------|
| 与 YiYi 对话 | 用户回答方向性问题，沉淀社交画像与偏好 |
| 网络垃圾桶 | 用户声明「不要什么」；YiYi 对外硬性过滤，触发则终止沟通 |
| YiYi ↔ YiYi 试探 | 系统匹配后，双方 YiYi 模拟沟通；判定 **有效** 才进入「YiYi 的消息」 |
| 权限与可见范围 | 用户控制对方主人是否可见沟通过程、是否允许加好友、YiYi 是否对外活跃 |

**维度三 · 差异化**：不是 Dating App 式直连；不是维度一的「熟人探索」（后者基于已填资料、面向已有联系人）。

**维度三 · 隐私**：画像用于 YiYi 对外表达，**不默认公开展示**；用户可随时修改权限与垃圾桶规则。

### 2.6 产品架构与 Tab 映射

```
AIChat
├── 维度一 · 关系社交
│   ├── 消息 Tab      → 真人私聊 + 素颜建议
│   ├── 群聊 Tab      → 护场群 + 搭子大厅
│   └── 朋友圈 Tab    → 探索好友 / 我的动态 / 热点 / 探索记录
├── 维度二 · 日常
│   └── 日常 Tab      → 私人记录（仅本机，仅自己可见）
├── 维度三 · YiYi
│   └── YiYi Tab      → 画像 / 对话 / 消息 / 权限 / 匹配
└── 基础层
    ├── 关系 Tab      → 联系人、好友请求
    └── 我的 Tab      → 账号、资料
```

**技术栈**：Vite + React 前端，Capacitor Android 壳，Node + Express 后端，WebSocket 实时消息，LLM 经服务端统一调用。

**全局原则**：AI 未配置时 **明确报错**，不做静默降级。

### 2.7 典型用户路径（按维度）

**维度一 · 关系社交**
1. **素颜**：暧昧私聊 → 打开素颜建议 → 选一条发送（保留主动权）。
2. **搭子**：创建「恋爱暧昧」群 → 拉好友 + 林小姐/周予安 → AI 接话点边界（抖音 30 秒成片）。
3. **探索式朋友圈**：填写「我的动态」→ 好友「探索」提问 → AI 基于资料回复。

**维度二 · 日常**
4. **通用**：日常 Tab → 拍照/写文字/语音 → 归档进 **个人生命轨迹**；只为本人留存。
5. **宝妈（典型）**：每日给娃拍照 → **直接记入日常**（不进系统相册杂糅）→ 按日回看「今天娃做了什么」→（V2+）月末 **一键生成成长记/短片**，自己先看，不必发朋友圈。

**维度三 · YiYi**
5. **YiYi**：与 YiYi 聊偏好 → 系统匹配 → 双方 YiYi 试探 → 有效则推送摘要 → 用户决定是否加好友。

### 4.2 维度一 · 关系社交：搭子与素颜付费策略

#### 4.2.1 总体判断（仅限维度一）

| 能力线 | 单品/分角色付费 | 可行性 | 产品策略 |
|--------|----------------|--------|----------|
| **搭子** | 不同护场角色单独付费 | **高** | **主推**：角色 IP 化，类似嘉宾包 / 皮肤 |
| **素颜** | 不同表达人格单独付费 | **中** | 可卖精选模板与联名人格；**须保留免费素颜与基础建议** |
| **探索式朋友圈** | — | **低** | V1 不收费；探索是维度一留存与信任基础 |
| **整维度锁付费** | 不付费则无法用关系社交 | **低** | **不做**：伤害抖音转化与 D7 留存 |

**结论**：搭子与素颜 **均可 monetize**，但路径不同——**搭子走「角色单品冲动消费」，素颜走「订阅 + 能力包」**；二者 catalog 独立，商城入口分开，避免用户混淆。

#### 4.2.2 搭子：按角色付费（主推 SKU）

**为何可行**

1. **价值感知清晰**：用户购买的是「林小姐帮我接话、点边界」，而非抽象的「AI 会员」。抖音传播已按角色建立认知（林小姐、周予安、阿跳等），**角色即商品**。
2. **场景驱动、付费意愿更强**：暧昧施压、采购扯皮、亲子沟通等场景中，一次有效「救场」的主观价值，高于日常输入法或通用 AI 聊天。
3. **与网络效应不冲突**：护场群需拉真人好友；若「不开会员不能建群」会扼杀冷启动。**免费 1 个通用搭子 + 热门角色单买**，传播与付费可并行。
4. **可持续上新**：按场景系列发布新角色（护场姐妹团、职场搭子等），形成类似游戏角色池的复购与内容营销素材。

**SKU 设计（参考）**

| SKU 类型 | 示例 | 定价区间（参考） |
|----------|------|------------------|
| 单角色永久解锁 | 林小姐、周予安 | ¥6–18 / 角色 |
| 单角色月卡 | 试用后转订阅 | ¥3–6 / 月 |
| 场景角色包 | 恋爱暧昧 3 人组 | ¥15–25 / 包 |
| 限时联名 / 新角色 | 节日/ KOL 联名 | 活动定价 |

**免费层底线**：至少 **1 个通用搭子** 永久免费，且 **建群、拉真人不受限**；抖音录屏与内测转化路径必须完整可走。免费角色接话质量须达标，避免「只有付费才说人话」的口碑风险。

**付费触点**：在 **搭子大厅 / 建群选角色** 环节转化；**禁止**在对方连发施压、群聊冲突高峰时弹付费窗（易被感知为「感情焦虑税」）。

#### 4.2.3 素颜：订阅与能力包（辅 SKU）

**为何不宜整功能锁付费**

素颜是 **高频工具**，用户会问「不付费是不是就不会聊天？」若基础建议被锁住，D1/D7 留存将明显受损。且 **自建素颜** 是产品护城河（越用越贴个人表达），与「必须买人格才能用」存在叙事冲突。

**推荐 monetize 方式**

| 方式 | 内容 | 说明 |
|------|------|------|
| 免费层 | 1–2 个素颜槽 + 每日 N 次建议 | 保证新用户完整体验 |
| 素颜 Pro 订阅 | 更多槽位、无限或更高频建议 | 主订阅项 |
| 精选模板包 | 职场 / 暧昧 / 边界感等场景模板 | 打包售卖，非单条计费 |
| 联名素颜（可选） | 素颜世界 KOL / 设计师合作款 | 逻辑同搭子单品，非核心盘 |

**可选单品**：素颜世界中的 **热门/联名人格** 可单买，但不替代免费默认素颜；与搭子商城分开展示。

#### 4.2.4 免费层与付费层总览（维度一）

```
维度一 · 关系社交 — 免费层（获客 + 留存 + 传播）
├── 素颜：1 个默认素颜 + 每日基础次数建议
├── 搭子：1 个通用搭子 + 建群与拉好友不限
├── 探索：基础探索与「我的动态」不限
└── 抖音 / 内测：护场群演示路径完整可用

维度一 · 关系社交 — 付费层
├── 搭子（主推）：单角色解锁 / 场景包 / 联名角色
├── 素颜（订阅为主）：Pro 槽位 + 建议频次 / 模板包
└── 会员打包：搭子任选 + 素颜 Pro

维度二 · 日常 — 免费层（V1）
└── 个人生命轨迹归档不限；不上传、不表演

维度二 · 日常 — 付费层（V2+，可选）
├── 扩容 / 加密备份 / 导出
└── AI 生命叙事：一键成文、一键成片（按次或订阅）

维度三 · YiYi — 暂不收费（验证期）
└── 匹配 PMF 确认后再设计
```

#### 4.2.5 定价与 ARPU 假设

| 用户类型 | 行为 | 月贡献（估算） |
|----------|------|----------------|
| 免费用户 | 只用默认搭子 + 基础素颜 | ¥0 |
| 搭子单品用户 | 购买 1–2 个角色 | ¥6–18（一次性摊销） |
| 素颜订阅用户 | 高频私聊辅助 | ¥15–25 / 月 |
| 会员用户 | 搭子 + 素颜打包 | ¥15–25 / 月 |

**API 成本约束**：搭子永久买断价需覆盖预期调用次数，或引导部分 SKU 采用月卡；长期避免纯低价永久买断导致 API 成本倒挂。

#### 4.2.6 需规避的产品与合规风险

| 风险 | 应对 |
|------|------|
| 冲突高峰弹付费 | 仅在角色大厅、建群前转化 |
| 免费角色过于鸡肋 | 免费搭子须具备真实护场能力 |
| 搭子与素颜混售 | 双 catalog、双商城，文案区分「群聊嘉宾」与「私聊表达」 |

| 未成年人场景 | 不对未成年恋爱等场景做诱导性付费设计 |

### 4.4 付费意愿验证计划（收费上线前）

| 实验 | 方法 | 决策标准 |
|------|------|----------|
| 角色付费排序 | 内测问卷：「愿为哪个搭子付 ¥9.9？」 | 确定首发付费角色与定价 |
| 免费 vs 试用 | A：永久 1 搭子；B：24h 全角色试用 | 对比 D7 留存与付费率 |
| 素颜限次 | A：10 次/天；B：无限（Pro） | 订阅转化 vs 流失率 |
| 触点 A/B | 大厅展示 vs 建群后提示 | 选择转化率更高且投诉更低的触点 |

若 **「指定搭子付费意愿」显著高于「更多素颜建议次数」**，则资源优先投入 **搭子角色商城与 IP 运营**。

### 10.1 产品三大维度
